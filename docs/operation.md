# 操作手册

本手册中的桌面端与 Chrome 扩展产品名称均为 `yet another downloader`。

## 下载一个浏览器视频

1. 双击发布版 App，或在源码目录启动 `pnpm tauri:dev`。启动页会显示“正在准备下载引擎”，并自动重试最多 3 次；首次解包可能需要约 30 到 60 秒。
2. 首次使用时点击顶部“帮助”并点击“准备扩展文件”，再按抽屉中的三步指引从 Chrome 加载扩展。
3. 在 Chrome 打开目标视频页面并播放几秒，让页面发出实际播放请求。
4. 对应视频元素右上角出现媒体悬浮卡片后，点击资源条即可提交下载；也可以点击扩展图标，在“发现的媒体”列表中选择资源。工具栏图标角标显示当前标签页捕获到的去重资源数量。
5. 扩展提交后会自动恢复并置前桌面端。任务依次可能显示：排队中、探测中、下载中、封装中、校验中、已完成。
6. 成功后在输出目录找到 MP4。任务只有通过视频流、时长、全文件数据包扫描、开头解码和长视频结尾解码检查后才会显示“已完成”。

每个视频只显示一个悬浮区域；同一视频检测到多个分辨率或不同码流时，会在区域内逐行展示，点击资源行即可下载，清单中可识别的变体会额外列出分辨率、码率和编码信息。切换到其他已捕获视频时，区域会切换到新视频而不会累积。点击码流右侧的红色 `×` 可以移除单条提示；点击面板顶部的 `×` 可以关闭当前视频的全部提示。

## 代理与请求头

扩展会捕获页面实际发送的 `User-Agent`、`Referer`、`Origin` 和 Cookie。HLS 任务由本地网关使用这些信息访问清单、密钥和分片；DASH 和直链任务由 yt-dlp 使用这些信息访问原始媒体地址。代理会按任务传给网关或 yt-dlp。

遇到 429 时，先确认代理可用，再降低任务并发或更换出口。网关只在 curl 层额外重试 1 次，并由 yt-dlp 或 PNG 任务层负责后续有限重试，避免多层重试相乘；单次上游请求最多等待 30 秒。这不能绕过服务端的永久封禁或失效的签名 URL。

## 任务管理

- 桌面端任务栏支持“全部、下载中、已完成、失败、已取消”筛选。
- 下载中任务显示实时速度、已下载/总字节数、分片进度和最后活动时间；出现代理或上游停滞时显示原因。
- 下载中任务可取消；失败或取消任务可“重新下载”。重试不会覆盖原记录，而是增加一次带尝试次数和父任务 ID 的记录。
- 已结束任务可“删除记录”，只删除历史元数据，不删除已生成的视频文件；“清理已完成”同样不删除视频文件。
- 已生成文件可点击“在 Finder 中显示”。该操作只接受存在的本地路径，不执行 shell 拼接。

## 调整任务

- 点击顶部“设置”打开抽屉，修改后点击抽屉外区域或关闭按钮返回任务区。
- 输出目录：设置抽屉中的“输出目录”。
- 代理：填完整 URL，例如 `http://127.0.0.1:7890`。
- 分片并发：默认 8，范围 1 到 16，仅对新任务生效。429 频繁时建议先降到 4；已经运行的任务需要取消后重新下载。
- 网络保护：yt-dlp 请求有 30 秒 socket 超时，分片最多重试 3 次并使用有上限的退避；HLS 网关的 curl 请求有 15 秒连接超时、30 秒总超时和 1 次轻量重试。代理失联时任务会失败并显示错误，不会无限卡在某个分片。
- 取消：任务在下载、转码、封装或校验阶段点击“取消”。网关会终止该任务自己启动的 curl/ffmpeg 子进程组，其他任务和 Python 引擎不受影响。
- 停滞保护：连续 90 秒没有进度会提示可能卡住，连续 180 秒会自动失败并允许重试。它不会修改正在运行的 yt-dlp 并发线程池。
- 输出保护：下载、转码和校验都在输出目录内的隐藏任务临时目录进行；只有全部校验通过后才原子移动到最终文件名。同名文件使用 `(2)`、`(3)` 编号，不覆盖已有视频。

## 历史与隐私

任务历史默认保存在 `~/Library/Application Support/m3u8-bridge/history.sqlite3`，设置文件仍为同目录下的 `settings.json`。SQLite 只保存标题、状态、进度、输出路径、尝试关系和 URL 指纹，不保存 Cookie、Authorization、完整签名 URL 或请求头。引擎重启后，数据库中的活动任务会显示为失败，需重新从浏览器捕获资源。

悬浮资源信息会尽量展示分辨率、码率、时长和编码。直链的分辨率/时长来自当前页面的 video 元数据，码率用文件大小除以时长估算；HLS/DASH 会尽力读取主清单中的全部变体。若浏览器跨域策略或清单不包含字段，则显示“媒体信息待探测”。

## 常见失败

### 引擎离线或异常退出

顶部状态区会显示“引擎离线”并提供“重启引擎”。点击后桌面端只会终止并重启自己管理的进程；如果提示端口冲突，需要先定位并关闭占用 8765 的旧版进程。点击“日志”可打开开发模式日志 `~/Library/Logs/m3u8-bridge/engine.log`。错误卡片默认展示中文处理建议，点击“技术详情”可查看和复制原始错误。

### 浏览器未能自动唤起桌面端

首次使用 `m3u8bridge://download` 时 Chrome 可能显示“打开外部应用”确认。允许后重新点击下载。若 60 秒内桌面端仍未启动，扩展会停止重试并提示手动打开应用；发布包中的 PyInstaller sidecar 首次解包可能需要数十秒。深链接不会携带视频地址或凭据。

### 桌面端显示等待本地引擎

发布版会在后台启动内置 sidecar，并在等待期间保留可见 Loading 页面。失败后顶部会出现“重启引擎”和“日志”；端口冲突时不会终止外部进程。源码开发模式需要 Miniforge Python 3.13 环境 `m3u8-bridge`，可单独运行 `scripts/run-engine.sh`，再访问 `http://127.0.0.1:8765/healthz`。

### 扩展没有资源

确认扩展加载的是最新的 `apps/chrome-extension/dist`，重新加载扩展后刷新页面并播放视频。扩展只展示视频响应，不展示 `.ts`、`.m4s`、`.aac`、`.vtt` 等常见分片。

### 任务失败且提示 URL 已失效

多数签名播放列表是一次性地址。回到页面重新播放，重新捕获并提交新任务。不要把 Cookie 或完整授权 URL 写入工单、日志或脚本。

### 输出文件不能播放

查看任务错误信息，确认 ffprobe 和 ffmpeg 可执行；WebM、FLV、不兼容像素格式或不兼容 HEVC 标签会转为 H.264/AAC MP4。失败任务的隐藏临时目录会自动清理，未通过校验的文件不会发布为最终 MP4。
