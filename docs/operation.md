# 操作手册

本手册中的桌面端与 Chrome 扩展产品名称均为 `yet another downloader`。

## 下载一个浏览器视频

1. 双击发布版 App，或在源码目录启动 `pnpm tauri:dev`。启动页依次显示检查本地服务、准备 Python、启动进程、恢复设置与记录、载入 yt-dlp、验证 API，并显示耗时和尝试次数。成功后进入任务界面；首次解包可能需要约 30 到 60 秒。
2. 首次使用时点击顶部“帮助”并点击“准备扩展文件”，再按抽屉中的三步指引从 Chrome 加载扩展。
3. 在 Chrome 打开目标视频页面并播放几秒，让页面发出实际播放请求。
4. 对应视频元素右上角出现媒体悬浮卡片后，点击资源条即可提交下载；也可以点击扩展图标，在“发现的媒体”列表中选择资源。工具栏图标角标显示当前标签页捕获到的去重资源数量。
5. 扩展提交后会自动恢复并置前桌面端。任务依次可能显示：排队中、探测中、下载中、封装中、校验中、已完成。
6. 成功后在输出目录找到 MP4。任务只有通过视频流、时长、全文件数据包扫描、开头解码和长视频结尾解码检查后才会显示“已完成”。

每个视频只显示一个悬浮区域；同一视频检测到多个分辨率或不同码流时，会在区域内逐行展示，点击资源行即可下载，清单中可识别的变体会额外列出分辨率、码率和编码信息。切换到其他已捕获视频时，区域会切换到新视频而不会累积。点击码流右侧的红色 `×` 可以移除单条提示；点击面板顶部的 `×` 可以关闭当前视频的全部提示。

点击面板顶部“收起”，只保留资源计数和“展开/关闭”按钮。收起状态在当前页面内保持：新增资源、媒体信息更新、切换视频和滚动不会自动展开；刷新页面后恢复默认展开。展开列表最多占视频高度的一半（不超过 320px），资源过多时在列表内纵向滚动，不再持续向下覆盖视频。

## 代理与请求头

扩展会捕获页面实际发送的 `User-Agent`、`Referer`、`Origin` 和 Cookie。HLS 任务由本地网关使用这些信息访问清单、密钥和分片；DASH 和直链任务由 yt-dlp 使用这些信息访问原始媒体地址。代理会按任务传给网关或 yt-dlp。

YouTube 视频网页由 yt-dlp 专用解析器下载。扩展捕获的 Googlevideo CDN 资源会结合原始 `pageUrl` 回到该视频网页获取完整音视频，不直接保存浏览器请求的单轨或字节范围。CDN 的 Cookie、Authorization、Range、Host 和 Origin 不会转发给 YouTube 网页。缺少原始网页时请刷新页面重新捕获，或在桌面端直接粘贴视频网页。

遇到 429 时，先确认代理可用，再降低任务并发或更换出口。网关只在 curl 层额外重试 1 次，并由 yt-dlp 或 PNG 任务层负责后续有限重试，避免多层重试相乘；单次上游请求最多等待 30 秒。这不能绕过服务端的永久封禁或失效的签名 URL。

## 任务管理

- 手动创建：在桌面端任务栏点击“新建下载”，粘贴 YouTube 视频网页、HLS（`.m3u8`）、DASH（`.mpd`）或视频直链，并可填写任务名称。资源类型默认自动识别；YouTube 的 watch、短链接、shorts、embed、live 视频地址可直接识别。其他无媒体扩展名的链接需要手动选择 HLS、DASH 或视频直链。点击“开始下载”后，新任务会出现在列表中。任务沿用“设置”中的输出目录、代理与并发；其他普通网页 URL 不属于媒体地址，需要 Cookie 或特殊请求头的资源请用 Chrome 扩展捕获。
- 桌面端任务栏支持“全部、下载中、已完成、失败、已取消”筛选。
- 下载中任务显示实时速度、已下载/总字节数、分片进度和最后活动时间；出现代理或上游停滞时显示原因。
- 下载结束后进度条切换为当前处理阶段：合并封装、转码为 H.264、完整文件扫描、首尾解码校验。FFmpeg 阶段显示实际处理时长、阶段百分比、处理倍速和耗时；不知道总时长或 yt-dlp 内部合并未提供进度时显示等待动画，不沿用下载百分比。完成快启动索引写入和输出验证前不会宣称任务完成。
- AV1 等不兼容编码需要软件转码为 H.264，可能明显慢于下载。转码保留取消、180 秒无输出停滞保护和 24 小时硬上限，不再因固定 15 分钟总时限中断有持续进度的长视频。
- 下载中任务可取消；失败或取消任务可“重新下载”。重试不会覆盖原记录，而是增加一次带尝试次数和父任务 ID 的记录。
- 已结束任务可“删除记录”，只删除历史元数据，不删除已生成的视频文件；“清理已完成”同样不删除视频文件。
- 已生成文件可点击“在 Finder 中显示”。该操作只接受存在的本地路径，不执行 shell 拼接。

## 后台运行与退出

- 点击窗口左上角关闭按钮只会隐藏主窗口，下载引擎和进行中的任务继续运行。
- macOS 菜单栏会常驻应用图标；存在活动任务时，图标旁显示所有活动任务的合计实时速度。
- 左键点击菜单栏图标可恢复并置前主窗口。
- 右键点击菜单栏图标可查看当前下载状态、打开主窗口或选择“退出 yet another downloader”。只有选择退出、使用系统退出命令或结束进程才会真正关闭应用并停止桌面端管理的下载引擎。
- 引擎暂时重启或令牌更新时，菜单栏会自动重新连接；短暂连接失败不会中止下载任务。

## 调整任务

封装阶段区分合并封装、H.264 转码、完整文件扫描及首尾解码校验；显示该阶段真实百分比、已处理媒体时长、倍速和耗时。无法取得时长时显示不定进度，不伪造百分比。AV1 等不兼容编码需要转码，耗时可能超过 15 分钟；有真实进展时不会被固定 900 秒总时限终止。连续 180 秒媒体时间、帧数和输出字节均无推进才停止，取消仍可用。H.264/兼容 HEVC 尽量直接封装，必要转码采用 veryfast 预设（相同质量下文件可能更大）。

后处理失败会保留输出目录中的隐藏任务目录，并在错误详情给出路径；其中原始下载和部分转码文件均未通过最终校验，不视为成功视频。可用 FFmpeg 单独处理保留的原始媒体；当前“重新下载”仍从源站开始。删除历史不删除这些保留文件，请手动管理磁盘空间。

- 点击顶部“设置”打开抽屉，修改后点击抽屉外区域或关闭按钮返回任务区。
- 输出目录：设置抽屉中的“输出目录”。
- 代理：填完整 URL，例如 `http://127.0.0.1:7890` 或 `socks5h://127.0.0.1:7890`（由代理端解析域名）。不会自动切换协议；留空明确关闭代理，不继承启动终端的代理环境变量。HLS 的外网请求使用该代理，yt-dlp 到本地中继的请求始终直连，避免本地请求绕回代理。
- 分片并发：默认 8，范围 1 到 16，仅对新任务生效。429 频繁时建议先降到 4；已经运行的任务需要取消后重新下载。
- 网络保护：yt-dlp 请求有 30 秒 socket 超时，分片最多重试 3 次并使用有上限的退避；HLS 网关的 curl 请求有 15 秒连接超时、30 秒总超时和 1 次轻量重试。代理失联时任务会失败并显示错误，不会无限卡在某个分片。
- 取消：任务在下载、转码、封装或校验阶段点击“取消”。网关会终止该任务自己启动的 curl/ffmpeg 子进程组，其他任务和 Python 引擎不受影响。
- 停滞保护：连续 90 秒没有进度会提示可能卡住，连续 180 秒会自动失败并允许重试。它不会修改正在运行的 yt-dlp 并发线程池。
- 输出保护：下载、转码和校验都在输出目录内的隐藏任务临时目录进行；只有全部校验通过后才原子移动到最终文件名。同名文件使用 `(2)`、`(3)` 编号，不覆盖已有视频。

## 历史与隐私

任务历史默认保存在 `~/Library/Application Support/m3u8-bridge/history.sqlite3`，设置文件仍为同目录下的 `settings.json`。SQLite 只保存标题、状态、进度、输出路径、尝试关系和 URL 指纹，不保存 Cookie、Authorization、完整签名 URL 或请求头。引擎重启后，数据库中的活动任务会显示为失败，需重新从浏览器捕获资源。

悬浮资源信息会尽量展示分辨率、码率、时长和编码。直链的分辨率/时长来自当前页面的 video 元数据，码率用文件大小除以时长估算；HLS/DASH 会尽力读取主清单中的全部变体。若浏览器跨域策略或清单不包含字段，则显示“媒体信息待探测”。

## 常见失败

### 引擎离线或异常退出

启动失败时保留阶段面板和技术详情，并提供“重新检查并启动”。真实冲突会显示监听 8765 的进程名称和 PID；它也可能是其他项目的 Web 服务，而非旧版引擎。可运行 `lsof -nP -iTCP:8765 -sTCP:LISTEN` 核实，将该服务改用其他端口或自行关闭后重试。活动监视器的普通进程列表不直接展示监听端口。

健康检查超时会显示等待或超时原因，不再直接误报端口冲突；首次组件解包期间保持启动页可见。点击“日志”可打开 `~/Library/Logs/m3u8-bridge/engine.log`，开发版和发布版都记录引擎输出。重启在后台进行，且只终止桌面端自身管理的进程。应用继续使用固定端口 8765，以保持 Chrome 扩展兼容。

成功的 GET/HEAD 轮询、HLS 分片和 OPTIONS 请求不写访问日志；失败响应、任务创建/删除等操作、引擎启动及任务状态变化仍保留。`Read timed out` 表示等待响应超时，不等于本地代理端口未监听；请区分目标站点响应缓慢、代理节点故障、本地中继请求被代理和签名地址过期。更换代理节点可能改变出口 IP，使绑定 IP 的签名地址失效，需要重新捕获。

### 浏览器未能自动唤起桌面端

首次使用 `m3u8bridge://download` 时 Chrome 可能显示“打开外部应用”确认。允许后重新点击下载。若 60 秒内桌面端仍未启动，扩展会停止重试并提示手动打开应用；发布包中的 PyInstaller sidecar 首次解包可能需要数十秒。深链接不会携带视频地址或凭据。

### 桌面端显示等待本地引擎

发布版会在后台启动内置 sidecar，并在等待期间保留可见 Loading 页面。失败后顶部会出现“重启引擎”和“日志”；端口冲突时不会终止外部进程。源码开发模式需要 Miniforge Python 3.13 环境 `m3u8-bridge`，可单独运行 `scripts/run-engine.sh`，再访问 `http://127.0.0.1:8765/healthz`。

### 扩展没有资源

确认扩展加载的是最新的 `apps/chrome-extension/dist`，重新加载扩展后刷新页面并播放视频。扩展只展示视频响应，不展示 `.ts`、`.m4s`、`.aac`、`.vtt` 等常见分片。

### 任务失败且提示 URL 已失效

多数签名播放列表是一次性地址。回到页面重新播放，重新捕获并提交新任务。不要把 Cookie 或完整授权 URL 写入工单、日志或脚本。

### 输出文件不能播放

查看任务错误信息，确认 ffprobe 和 ffmpeg 可执行；WebM、FLV、不兼容像素格式或不兼容 HEVC 标签会转为 H.264/AAC MP4。失败任务的隐藏临时目录会自动清理，未通过校验的文件不会发布为最终 MP4。

若提示“资源不是完整视频”，说明下载结果没有视频轨，可能是音频轨或不完整资源。不要通过把 `-map 0:v:0` 改成可选来绕过校验；请使用视频网页或重新捕获完整媒体。YouTube 专用解析失败时会保留原始错误，不再退回 curl 下载网页。文件选择优先采用 yt-dlp 的最终合并路径，并拒绝 `.part`、`.ytdl` 和分轨临时文件。
